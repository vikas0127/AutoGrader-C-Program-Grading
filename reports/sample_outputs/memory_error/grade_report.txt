USEFULNESS IN REAL-LIFE SETTINGS
--------------------------------------------------
- Large programming courses: Apply one test suite and rubric to hundreds of submissions.
  Benefit: Consistent, repeatable grading and faster feedback.
- Introductory programming feedback: Show an input that causes a wrong answer with expected and actual output.
  Benefit: Students can reproduce and debug failures.
- Code-quality screening: Report warning, structure, modularity and readability indicators.
  Benefit: Instructor can assess more than output correctness.
- Originality triage: Flag submissions above a configurable source similarity threshold.
  Benefit: Focus human review on candidate pairs; does not prove copying.

CONCRETE LIMITATIONS
--------------------------------------------------
- Finite tests do not prove correctness: A program passes supplied tests but fails an untested extreme input.
- Sanitizers only detect executed defects: An invalid access exists in a branch none of the supplied inputs reach.
- Similarity can have false positives and negatives: A short mandated solution looks similar, or copied code is heavily refactored.
- Heuristic source analyzers can misestimate properties: A loop bound depends on input in a way the lexical estimator does not recognize.

LIMITATIONS
--------------------------------------------------
- POSIX resource limits are not a complete security sandbox; use a disposable lab container/VM for untrusted code.
- Sanitizers detect only errors triggered by supplied test inputs.
- Complexity, structure, readability and similarity are heuristic.
- A similarity flag is not proof of plagiarism or LLM use.
